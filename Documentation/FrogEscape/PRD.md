# Project Frog Escape
## Unity 기반 3D 아케이드 추격 게임 개발 PRD

**문서 버전:** 1.0  
**개발 환경:** Unity / C# / Codex  
**개발 목적:** 학교 정보축전 체험형 게임  
**대상 사용자:** 초등학생 및 중학교 1~2학년  
**목표 플레이 시간:** 약 3~5분  
**참고 작품:** Crazy Frog – Axel F 뮤직비디오의 추격 장면

---

# 1. 프로젝트 개요

## 1.1 개발 배경

현재 Unity로 구현된 F1 스타일 레이싱 게임은 차량 가속, 제동, 변속, 코너링과 같은 조작 요소 때문에 저연령층의 진입 장벽이 높다.

따라서 기존 레이싱 중심의 게임에서 벗어나, Crazy Frog 밈의 추격 연출을 참고한 간단한 아케이드 게임을 신규 개발한다.

본 프로젝트는 단순한 장애물 회피 게임이 아니라, **3단계에 걸쳐 추격자의 행동과 위협 요소가 변화하는 시네마틱 추격 액션 게임**을 목표로 한다.

## 1.2 핵심 목표

1. 초등학생도 10~20초 내에 조작법을 이해할 수 있도록 설계한다.
2. 자동 전진 시스템으로 복잡한 차량 조작을 제거한다.
3. 고가도로, 지하수로, 야외 추격전으로 이어지는 3단계 스테이지를 제작한다.
4. 추격 경찰에게 상황 판단, 경로 추종, 장애물 회피, 공격 타이밍 결정 기능을 구현한다.
5. 씬 전환에 시네마틱 카메라와 애니메이션을 적용한다.
6. 마지막 유도탄 역이용 장면을 엔딩 컷신으로 제작한다.
7. 일반적인 플레이 기준 3~5분 안에 결말에 도달하도록 설계한다.

## 1.3 핵심 게임 루프

게임 시작 → 자동 주행 → 추격자 등장 → 장애물 또는 공격 예고 → 플레이어 회피 → 생존 판정 → 다음 구간 진입 → 최종 회피 → 엔딩

**핵심 설계 원칙:** 조작은 간단하게, 회피 패턴은 다양하게, 장면 전환은 화려하게 구성한다.

# 2. 전체 게임 구조

## 2.1 스테이지 구성

| 구간 | 주요 배경 | 핵심 요소 | 권장 시간 |
|---|---|---|---|
| Stage 1 | 도시 고가도로 | 기본 주행 및 경찰 추격 | 50~70초 |
| Transition 1 | 고가도로 외벽 | 벽타기 및 지하수로 진입 | 8~12초 |
| Stage 2 | 지하수로 | 경찰 탄환 회피 | 60~75초 |
| Transition 2 | 수로 출구 | 외부 탈출 및 유도탄 등장 | 8~12초 |
| Stage 3 | 외부 도로 | 유도탄 추적 및 회피 | 60~80초 |
| Ending | 최종 도로 구간 | 유도탄 역이용 및 탈출 | 15~20초 |

기본 목표는 약 4분이며, 사용자의 숙련도에 따라 실제 시간은 달라질 수 있다.

## 2.2 진행 구조

- 스테이지 1, 2, 3은 서로 독립적인 Unity Scene으로 구성한다.
- 전환 컷신은 Unity Timeline 기반으로 구현한다.
- 컷신은 플레이어 조작을 잠시 제한하고 자동 실행한다.
- 스테이지 종료 및 다음 스테이지 로드는 StageManager가 담당한다.
- 로딩 중 화면이 끊어지는 현상을 최소화한다.
- 승리 시 Ending Scene을 실행한다.
- 체험 행사 운영을 위해 시작 화면으로 돌아가기 및 재시작 기능을 제공한다.

# 3. 플레이어 시스템

## 3.1 조작 방식

| 입력 | 기능 |
|---|---|
| A / 왼쪽 방향키 | 좌측 이동 |
| D / 오른쪽 방향키 | 우측 이동 |
| Space | 회피 동작 |
| ESC | 일시정지 |
| Enter | 메뉴 선택 및 시작 |

자동 가속 방식이며 수동 변속과 브레이크는 제공하지 않는다.

Space는 짧은 회피 동작을 실행하는 키로 사용한다. 회피 애니메이션은 스테이지에 따라 달라질 수 있으나 조작 키는 동일하게 유지한다.

## 3.2 이동 시스템

플레이어는 지정된 도로 경로를 따라 자동으로 전진한다.

필수 기능:

- 경로 기반 자동 전진
- 좌우 자유 이동
- 도로 경계를 벗어나지 않도록 이동 제한
- 카메라 기준으로 직관적인 좌우 입력
- 조작 입력 보간을 통한 부드러운 움직임
- 충돌 후 위치 복구
- 일정 시간 피격 무적
- 회피 동작 실행 및 쿨다운 관리

기존 F1 차량의 복잡한 휠 물리 엔진을 그대로 적용할 필요는 없다.

**최우선 목표는 실제 차량의 물리적 정확성이 아니라 플레이어의 조작 편의성과 반응성이다.**

## 3.3 카메라 시스템

기본 시점은 플레이어 뒤쪽에서 바이크와 전방 도로를 볼 수 있는 3인칭 추적 카메라다.

필수 연출:

- 플레이어 이동에 따라 부드럽게 회전
- 속도에 따른 FOV 변화
- 경찰이 가까워지면 긴장감을 주는 카메라 효과
- 공격 경고 시 시야 확보
- 회피 성공 시 짧은 시각적 피드백
- 씬 전환 시 시네마틱 카메라로 전환

과도한 화면 흔들림이나 모션 블러는 저연령층의 플레이를 방해할 수 있으므로 제한한다.

# 4. Stage 1 — 고가도로 추격전

## 4.1 스테이지 개요

**배경:** 도시 고가도로 및 곡선형 고속도로  
**목표:** 경찰을 피해 도로 끝까지 이동  
**주요 목적:** 기본 조작 학습

Crazy Frog 원본 영상 초반의 고가도로 분위기를 참고하여 제작한다.

## 4.2 맵 구성

맵에는 다음 요소를 포함한다.

- 높이 차이가 있는 도시 고가도로
- 콘크리트 방호벽
- 여러 개의 곡선 도로
- 도시 건물 배경
- 도로 표지판과 가로등
- 제한적인 교통 차량
- 마지막 벽타기 진입 구간

도로는 단순 직선이 아니라 카메라 연출을 활용할 수 있는 곡선 구간을 포함한다.

그러나 급격한 방향 전환으로 플레이어가 길을 잃지 않도록 경로 추종 시스템을 적용한다.

## 4.3 플레이 방식

스테이지 시작 시 플레이어는 고가도로를 달리고 있으며, 뒤에서 경찰 차량이 등장한다.

진행 단계:

1. 플레이어 자동 주행 시작
2. 좌우 이동 조작 안내
3. 기본 장애물 등장
4. 경찰 추격 시작
5. 경찰 AI가 플레이어의 이동 경로를 따라감
6. 교통 차량 및 장애물 회피
7. 도로 끝에 도달하면 컷신 실행

Stage 1에서는 경찰이 투사체 공격을 하지 않는다.

## 4.4 장애물 시스템

장애물은 미리 정의된 안전한 배치 규칙에 따라 생성한다.

- 정지 차량
- 도로 공사 시설
- 콘크리트 장애물
- 이동 차량

장애물 생성 시 플레이어가 회피할 수 있는 이동 공간을 반드시 확보한다.

첫 장애물은 조작을 익힐 수 있도록 충분히 일찍 표시한다.

## 4.5 클리어 조건

정해진 추격 구간을 통과하면 자동으로 첫 번째 전환 컷신을 시작한다.

# 5. Transition 1 — 벽타기 및 지하수로 진입

## 5.1 연출 목표

Crazy Frog의 벽을 타고 올라간 뒤 떨어지는 장면을 참고하여, 고가도로에서 지하수로로 이어지는 인상적인 전환을 제작한다.

## 5.2 컷신 시퀀스

1. 도로 끝에서 경찰이 빠르게 접근한다.
2. 플레이어는 방호벽과 연결된 경사 구조물을 향해 달린다.
3. 바이크가 벽면을 따라 위쪽으로 이동한다.
4. 카메라가 측면으로 전환된다.
5. 잠깐 공중에 떠오르는 연출을 실행한다.
6. 플레이어가 아래쪽 수로 방향으로 내려간다.
7. 카메라가 플레이어를 따라 하강한다.
8. 지하수로로 착지한다.
9. Stage 2가 시작된다.

## 5.3 구현 요구사항

- Unity Timeline 사용
- 카메라 위치 및 회전 애니메이션
- 플레이어 위치 보간
- 벽면 주행 및 공중 동작 애니메이션
- 지하수로 도착 시 자연스러운 착지
- 플레이어 입력 잠금 및 복구

벽타기 동작은 일반 플레이 물리 시뮬레이션이 아니라 사전에 제작된 컷신으로 구현한다.

씬 로딩은 컷신의 카메라 전환이나 화면 가림 구간과 연결한다.

---

# 6. Stage 2 — 지하수로 추격전

## 6.1 스테이지 개요

**배경:** 대형 콘크리트 지하수로  
**목표:** 경찰의 탄환을 피하면서 수로를 탈출  
**추가 요소:** 공격 예고 및 타이밍 회피

## 6.2 맵 구성

Crazy Frog의 지하수로 배경을 참고한다.

주요 환경:

- 넓은 콘크리트 수로
- 경사진 좌우 벽
- 터널 구조물
- 교량 및 배수 통로
- 얕은 물과 반사 효과
- 수로 측면의 경찰 이동 경로
- 지상으로 이어지는 출구

바이크는 수로 중앙의 건조하거나 얕은 구간을 중심으로 주행한다.

## 6.3 경찰 공격 시스템

Stage 2부터 경찰은 추격과 함께 만화적인 탄환 발사 패턴을 사용한다.

공격 패턴은 다음 단계로 실행한다.

**Targeting → Warning → Fire → Dodge Check → Recovery**

### Targeting

- 경찰 AI가 플레이어의 현재 위치와 이동 방향을 관찰한다.
- 짧은 미래 위치를 예상해 공격 구역을 선택한다.
- 화면 밖에서 불합리하게 피격되지 않도록 공격 방향을 제한한다.

### Warning

- 공격 전 조준 표시 또는 경고선이 나타난다.
- 공격 방향을 시각적으로 알려준다.
- 플레이어에게 충분한 반응 시간을 제공한다.

### Fire

- 경찰이 만화적인 투사체를 발사한다.
- 투사체는 화면에서 식별하기 쉬워야 한다.
- 투사체가 플레이어에게 도달하기 전에 회피할 시간을 제공한다.

### Dodge Check

- 플레이어가 좌우로 이동하거나 Space 회피를 사용하면 공격을 피할 수 있다.
- 충돌 판정은 명확하고 일관되게 작동해야 한다.

### Recovery

- 공격이 종료된 후 짧은 대기 시간이 발생한다.
- 다음 공격 전 플레이어의 안전한 이동을 허용한다.

## 6.4 공격 패턴 종류

| 패턴 | 설명 | 난이도 |
|---|---|---|
| Single Shot | 하나의 구역을 향한 단발 공격 | 쉬움 |
| Double Shot | 시간차로 두 번 공격 | 보통 |
| Predictive Shot | 플레이어 이동 방향을 예상하는 공격 | 보통 |

기본 체험 모드에서는 공격 패턴을 하나씩 보여주고, 동시에 여러 개의 위협을 겹치지 않는다.

## 6.5 클리어 조건

정해진 수로 구간을 통과하면 탈출 컷신이 시작된다.

---

# 7. Transition 2 — 지하수로 탈출 및 유도탄 등장

## 7.1 연출 목표

플레이어가 수로를 빠져나와 도로로 복귀하는 순간 경찰이 새로운 추적 장치를 발사하면서 Stage 3으로 전환한다.

## 7.2 컷신 구성

1. 플레이어가 수로 끝의 경사로로 접근한다.
2. 바이크가 경사로를 따라 외부로 상승한다.
3. 카메라가 넓은 야외 도로를 보여준다.
4. 경찰이 플레이어를 발견한다.
5. 경찰 측에서 만화적인 유도탄이 발사된다.
6. 유도탄이 플레이어 뒤쪽에서 따라오기 시작한다.
7. 화면에 유도탄 경고 UI가 등장한다.
8. Stage 3의 주행이 시작된다.

## 7.3 필수 구현

- 경사로 탈출 애니메이션
- 야외 환경 전환
- 유도탄 등장 연출
- 경고음 및 시각 효과
- 플레이어의 정상 이동 복구

---

# 8. Stage 3 — 유도탄 회피 추격전

## 8.1 스테이지 개요

**배경:** 도시 외부 도로 및 넓은 추격 구간  
**목표:** 유도탄의 추적을 피해 마지막 공격까지 생존  
**핵심 요소:** 회피 타이밍 판단

## 8.2 유도탄 AI 시스템

유도탄은 단순히 플레이어의 위치로 순간 이동하거나 직선으로만 이동해서는 안 된다.

다음 기능을 갖는 게임용 추적 시스템을 구현한다.

- 플레이어 위치 추적
- 이동 방향에 따른 제한적인 경로 예측
- 회전 속도 제한
- 최대 속도 설정
- 공격 전 경고
- 마지막 접근 구간에서의 돌진
- 플레이어 회피 성공 판정
- 실패 시 피해 판정
- 발사 후 자동 정리

유도탄은 실제 무기 성능을 재현하는 목적이 아니라 아케이드 게임의 회피 대상이다.

## 8.3 공격 상태 머신

**Spawn → Pursue → LockOn → Warning → Dash → Hit/Miss → Despawn**

| 상태 | 기능 |
|---|---|
| Spawn | 유도탄 생성 및 초기 연출 |
| Pursue | 플레이어 뒤를 따라 추적 |
| LockOn | 최종 접근을 위한 추적 상태 |
| Warning | 경고 표시 및 회피 타이밍 제공 |
| Dash | 플레이어를 향해 마지막 돌진 |
| Hit/Miss | 충돌 또는 회피 결과 판정 |
| Despawn | 투사체 제거 및 다음 패턴 준비 |

## 8.4 회피 메커니즘

- 유도탄이 플레이어에게 접근한다.
- 화면에 경고 표시가 나타난다.
- 경고 단계가 진행되면서 색상이나 점멸 속도가 변화한다.
- 회피 가능한 타이밍에 명확한 시각적 신호를 제공한다.
- 플레이어가 Space를 누르면 짧은 회피 동작이 발동한다.
- 올바른 타이밍에 사용하면 추적 공격이 빗나간다.
- 너무 빠르거나 늦은 경우에는 충돌할 수 있다.

단, 초등학생 대상의 기본 모드에서는 회피 판정 시간을 충분히 넓게 설정한다.

## 8.5 공격 횟수

기본 스테이지는 유도탄 공격 3회로 구성한다.

**Wave 1: 단순 추적**

- 경고 시간이 길다.
- 유도탄의 추적 능력이 약하다.
- Space 사용 타이밍을 익힌다.

**Wave 2: 강화 추적**

- 유도탄이 플레이어의 좌우 이동에 반응한다.
- 경고 후 돌진 속도가 증가한다.
- 플레이어의 타이밍 판단을 요구한다.

**Wave 3: 최종 공격**

- 경찰이 마지막 유도탄을 발사한다.
- 회피 경고가 등장한다.
- 플레이어가 마지막 공격을 성공적으로 회피한다.
- 회피 성공과 동시에 엔딩 컷신으로 연결한다.

## 8.6 클리어 조건

마지막 유도탄 공격을 성공적으로 회피하면 Ending Scene을 실행한다.

기본 모드에서는 세 번째 공격 전에 플레이어의 상태가 지나치게 불리해지지 않도록 난이도를 제어한다.

# 9. Ending — 유도탄 역이용 엔딩

## 9.1 엔딩 컨셉

Crazy Frog의 코믹한 역전 연출을 참고하여, 추격당하던 플레이어가 마지막 유도탄을 역이용해 경찰의 추격을 따돌린다.

## 9.2 시네마틱 순서

1. 마지막 유도탄이 플레이어를 향해 접근한다.
2. 플레이어가 공격을 회피한다.
3. 카메라가 슬로모션으로 전환된다.
4. 플레이어가 점프하여 유도탄 위에 올라탄다.
5. 잠깐 균형을 잡는 코믹한 애니메이션이 실행된다.
6. 유도탄의 진행 방향이 경찰 쪽으로 바뀐다.
7. 플레이어가 안전한 방향으로 뛰어내린다.
8. 유도탄이 경찰 차량 쪽으로 날아간다.
9. 화면 밖에서 과장된 만화식 충돌 효과가 나타나고 추격이 종료된다.
10. 플레이어가 유유히 도로를 빠져나간다.
11. 화면에 게임 클리어 문구가 나타난다.

## 9.3 엔딩 구현 방식

- Timeline 기반 완전 자동 컷신
- 플레이어와 유도탄의 위치를 사전 정의된 경로로 제어
- 슬로모션 및 카메라 전환
- 코믹한 효과음
- 과장된 파티클 효과
- CLEAR UI
- 재시작 및 타이틀 복귀

마지막 유도탄 위에 올라타는 동작은 실제 물리 엔진으로 구현할 필요가 없다.

애니메이션으로 자연스럽게 연결하는 것을 우선한다.

엔딩은 그래픽한 피해 묘사 없이 코믹한 연출로 마무리한다.

# 10. 경찰 추격 AI

## 10.1 AI 설계 목적

경찰은 단순한 배경 장식이 아니라 플레이어의 움직임에 반응하는 추격 AI로 구현한다.

정보축전의 교육적 목표를 고려하여 경로 추종, 장애물 감지, 행동 판단 등의 기능을 포함한다.

## 10.2 상태 머신

| AI 상태 | 동작 |
|---|---|
| Patrol | 정해진 경로를 따라 이동 |
| Chase | 플레이어의 위치를 추적 |
| Avoid | 주변 장애물을 감지하고 회피 |
| Reposition | 공격 가능한 위치로 이동 |
| Attack | 스테이지별 공격 실행 |
| Recover | 공격 후 대기 및 재정렬 |
| Cinematic | 컷신 중 사전 정의된 행동 수행 |

## 10.3 플레이어 추적

- 플레이어의 현재 위치를 갱신한다.
- 주행 경로를 따라 추격한다.
- 플레이어와 경찰 사이의 거리를 계산한다.
- 거리에 따라 추격 속도를 조절한다.
- 경찰 차량이 장애물과 충돌하지 않도록 회피한다.
- 경찰이 플레이어를 지나쳐서 화면 밖으로 사라지는 현상을 방지한다.

무조건적인 순간 이동은 금지하며, 예외적인 복구가 필요하면 화면 밖에서 자연스럽게 처리한다.

## 10.4 난이도별 AI 변화

기본 난이도에서는 경찰이 지나치게 공격적으로 행동하지 않는다.

난이도 상승은 주로 다음 요소로 구현한다.

- 추격 속도
- 공격 간격
- 경고 시간
- 플레이어 위치 예측 정도
- 공격 패턴 다양성

추적 상태나 공격 상태의 전환은 개발자가 Unity Inspector에서 확인하고 조절할 수 있도록 한다.

## 11.1 난이도 선택

| 요소 | Easy (기본) | Normal |
|---|---|---|
| 체력 | 4 | 3 |
| 기본 이동 속도 | 낮음 | 보통 |
| 장애물 밀도 | 낮음 | 보통 |
| 공격 경고 | 길게 | 보통 |
| 유도탄 회피 판정 | 넓음 | 보통 |

모든 수치는 초기 설계값이며 실제 플레이 테스트 후 변경할 수 있어야 한다.

## 11.2 실패 처리

- 피해를 받을 때 체력이 1 감소한다.
- 피격 직후 일시적으로 무적 상태가 된다.
- 체력이 0이 되면 실패 화면이 등장한다.
- 현재 스테이지 재시작을 지원한다.
- 게임 전체를 처음부터 다시 시작하도록 강제하지 않는다.

체험 행사에서는 여러 사용자가 빠르게 교대하므로 실패 후 재도전 과정도 짧아야 한다.

## 11.3 튜토리얼

Stage 1 시작 시 화면에 조작법을 간단하게 표시한다.

- A/D: 좌우 이동
- Space: 회피
- 경찰을 피해 탈출하세요!

Stage 2 최초 공격과 Stage 3 최초 유도탄 공격에서는 별도 안내를 표시한다.

튜토리얼은 긴 설명 화면 대신 실제 게임 진행 속에서 학습하도록 구성한다.

초등학생 및 중학생을 대상으로 다음 사항을 확인한다.

- 별도 설명 없이 기본 조작을 이해하는가?
- 첫 장애물에 대응할 시간이 충분한가?
- 공격 경고가 직관적인가?
- 유도탄 회피 타이밍을 학습할 수 있는가?
- 실패 원인을 쉽게 이해할 수 있는가?
- 3~5분 안에 게임을 끝낼 수 있는가?

정량적인 테스트 목표는 다음과 같다.

- 기본 조작 이해: 20초 이내
- 기본 난이도에서 첫 스테이지 완료율: 목표 90% 이상
- 전체 게임 1~2회 시도 내 완료율: 목표 70% 이상
- 평균 완료 시간: 3~5분

위 수치는 실제 실험 결과가 아니라 초기 품질 목표다.

# 16. Codex 개발 지침

이 PRD를 전달받은 Codex는 다음 개발 규칙을 따른다.

## 16.1 프로젝트 분석 우선

코드를 즉시 대량 생성하지 말고 먼저 다음을 확인한다.

- 현재 프로젝트의 Unity 버전
- 사용 중인 Input System
- Render Pipeline
- 설치된 패키지
- 기존 차량 이동 코드
- 기존 UI 및 카메라 코드
- 기존 Scene 구조
- 현재 Console Error
- 활용 가능한 3D 모델 및 애니메이션

분석이 완료되면 신규 프로젝트 구조와 기존 기능 재사용 계획을 간단하게 기록한다.

## 16.2 기존 기능 보호

- 기존 F1 Scene 삭제 금지
- 기존 게임의 플레이 동작을 임의로 변경하지 않기
- 핵심 Controller를 무분별하게 덮어쓰지 않기
- 새 기능은 가능한 독립적인 스크립트로 구현
- 변경 파일 목록 기록
- 가능하면 별도 Git 브랜치에서 작업

## 16.3 구현 원칙

- 핵심 기능부터 구현한다.
- 초기에는 임시 3D 오브젝트를 활용한다.
- 기능 검증 후 모델 및 연출을 추가한다.
- 게임 로직과 연출 로직을 분리한다.
- Inspector에서 주요 파라미터를 조정할 수 있도록 한다.
- 씬 간 종속성을 최소화한다.
- 예외 상황과 객체 해제를 처리한다.
- 하드코딩된 씬 이름이나 오브젝트 탐색에 과도하게 의존하지 않는다.

## 16.4 검증 원칙

각 Phase 완료 후 다음을 수행한다.

1. 컴파일 오류 확인
2. Unity Console 확인
3. 관련 Scene 및 GameObject 구성 확인
4. 가능한 경우 Play Mode 직접 실행
5. 기능별 입력과 결과 검증
6. 발생 오류 수정
7. 기능 테스트 결과 기록
8. 남아 있는 문제와 다음 작업 제시

실제 Unity 실행이나 조작을 수행하지 못한 경우에는 검증 완료라고 표현하지 않는다.

# 18. 최종 개발 목표

본 프로젝트의 최종 목표는 단순한 F1 레이싱 게임의 조작 단순화가 아니다.

**고가도로 추격전 → 벽타기 → 지하수로 회피전 → 수로 탈출 → 유도탄 추격전 → 유도탄 역이용 엔딩**으로 이어지는 하나의 완성된 체험형 게임을 제작하는 것이다.

플레이어는 쉬운 조작으로 다양한 추격 패턴을 경험하고, 게임 내부에서는 경찰 AI의 경로 추종, 목표 예측, 장애물 회피, 상태 전환 알고리즘이 작동하도록 한다.

**최종 성공 기준: 초등학생도 쉽게 시작할 수 있고, 짧은 플레이 안에 추격의 긴장감과 코믹한 엔딩의 재미를 모두 경험할 수 있는 Unity 게임.**
